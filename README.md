## Setup — Repository จริง

### 1. วาง baseline ลง repository และ commit ก่อน

วางไฟล์ทั้งหมดที่ repository root แล้วสร้าง baseline commit ก่อน initialize Spec Kit เพื่อให้ตรวจ diff/rollback ได้ชัดเจน

### 2. ตรวจ CLI

```bash
specify check
specify version
```

### 3. Initialize Spec Kit ใน non-empty repository โดยให้ Claude เป็น default integration

```bash
specify init --here --force --integration claude
```

ตรวจ `git status` และ `git diff` หลัง init ก่อนทำขั้นถัดไป

### 4. ติดตั้ง Codex integration เพิ่ม

```bash
specify integration install codex
specify integration status
```

Spec Kit รุ่นปัจจุบันรองรับ Claude และ Codex แบบ multi-install safe โดยใช้คนละ directory:

```text
.specify/          ← shared Spec Kit infrastructure
.claude/skills/    ← Claude integration
.agents/skills/    ← Codex integration
specs/             ← generated by feature workflow
```

ให้ Claude remain เป็น default integration สำหรับ delivery workflow เว้นแต่ Product Owner ตั้งใจเปลี่ยน

## Implementation Unit = Authorized Implementation Scope

ตั้งแต่ workflow v1.2.0 **ไม่บังคับ 1 Task = 1 Run**

หนึ่ง implementation scope อาจเป็น:

```text
T006
```

หรือ bounded batch เช่น:

```text
T006–T009
```

โดย DEV ต้องอ่าน `tasks.md` และ Phase ปัจจุบันก่อนเลือก scope

### Batch ได้เมื่อครบหลักสำคัญ

- tasks อยู่ใน Phase เดียวกัน
- dependency พร้อมและไม่มี decision gate คั่นกลาง
- tasks เป็น technical concern ที่ต่อเนื่อง/สัมพันธ์กัน
- verification ของทั้ง batch ชัดเจน
- diff ยังมีขนาดที่ Reviewer ตรวจได้อย่างมีคุณภาพ
- ไม่มีการรวม high-risk business mutation หลายเรื่องโดยไม่จำเป็น

### ให้ลดกลับเป็น task เดี่ยวหรือ batch เล็กเมื่อเกี่ยวกับ

- security / authorization
- transaction / concurrency
- stock quantity / unit conversion integrity
- lifecycle/state transition สำคัญ
- audit/evidence integrity
- migration/destructive operation
- business rules ที่มีผลข้าม feature หรือมีความเสี่ยงสูง

ถ้าไม่แน่ใจ ให้เลือก scope ที่เล็กกว่า

Phase ใน `tasks.md` เป็น **input สำหรับ grouping** ไม่ใช่คำสั่งให้ทำทั้ง Phase อัตโนมัติ

## Implementation Scope Loop

```text
Product Owner authorizes current scope
        ↓
Claude implements authorized scope
        ↓
Tests / verification
        ↓
READY FOR INDEPENDENT REVIEW
        ↓
Codex reviews exact scope
   ┌──────────────┴──────────────┐
 PASS                 CHANGES REQUIRED
   │                         │
   │                    Claude reworks
   │                         ↓
   │                    Codex re-reviews
   └──────────────┬──────────────┘
                  ↓
           Product Owner gate
                  ↓
          Next bounded scope
```

Reviewer เป็น read-only และต้องตรวจ coverage ของทุก Task ID ที่อยู่ใน scope

## Three Independent Review Gates

1. **Delivery Readiness Review** — หลัง Analyze ก่อน implementation
2. **Implementation Scope Review** — หลังทุก authorized implementation scope/rework
3. **Final Feature Review** — หลัง Converge ก่อน Human Acceptance

Business clarification ยังคงเป็น Product Owner decision; Reviewer ไม่ตัดสิน business intent แทน Product Owner
